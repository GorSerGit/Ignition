# 📥 Парсинг текста и создание базы

Модуль отвечает за **первый этап жизненного цикла агента**: превращение сырого естественно-языкового текста в структурированную АГ-память.

Здесь живёт БЯМ-парсер (на базе GigaChat), который извлекает из текста факты в виде `predicate + template + roles`, а затем складывает их в SQLite-базу через модуль `agent.memory`.

---

## 📂 Состав

| Файл | Назначение |
|------|------------|
| `parser.py` | БЯМ-парсер: разбивает текст на группы предложений, отправляет в GigaChat, чистит JSON, обрабатывает ошибки с экспоненциальным backoff, восстанавливается после сбоев через хэширование чанков |
| `main.py` | Точка входа: загружает корпус из `data/input/`, запускает парсинг, выполняет дедупликацию связей, печатает статистику |
| `data_generation.py` | Генерирует `questions_dataset.csv` — контрольный датасет из 30 вопросов (уровни A, B, C) |
| `val.py` | Валидация графа: проверка ацикличности `IS-A` и `FOLLOW`, корректности весов, вывод полной текстовой карты графа |

---

## 🚀 Запуск

### 1. Подготовка корпуса

Положи PDF или TXT файлы в `data/input/`:

```
data/
└── input/
    ├── biology_textbook.pdf
    └── lecture_notes.txt
```

Ограничения хакатона:
- не менее **15 000 слов** в корпусе;
- не менее **150 уникальных абстрактных символов**;
- не менее **1000 гиперузлов и связей** в итоговом графе.

### 2. Построение АГ-памяти

Из **корня** проекта:

```bash
python -m parsing.main
```

С параметрами:

```bash
# Тестовый режим: обработать только 5 групп предложений
python -m parsing.main --test 5

# Полный сброс базы перед запуском
python -m parsing.main --reset
```

Результат:
- `data/output/ah_memory.db` — база АГ-памяти;
- в консоль выводится статистика: `S` (символы), `P` (факты), `L` (связи).

### 3. Генерация датасета вопросов

```bash
python parsing/data_generation.py
```

Создаст `questions_dataset.csv` с полями `question, reference_answer`.

### 4. Валидация графа

```bash
python -m parsing.val
```

Проверит:
- ✅ ацикличность иерархий `IS-A`;
- ✅ ацикличность эпизодов `FOLLOW`;
- ✅ корректность статистических весов (`w = count / (count + 1)`);
- 📊 выведет полную текстовую карту графа.

## ⚙️ Как работает парсер

1. **Разбиение** (`split_and_group`): текст режется по границам предложений, группируется по 3 предложения.
2. **Хэширование** (`get_chunk_hash`): каждая группа получает MD5-хэш — для восстановления после сбоев.
3. **Проверка** (`is_chunk_processed`): если чанк уже в БД — пропускается.
4. **Запрос к GigaChat**: жёсткий промпт `SYSTEM_PROMPT_GROUP` требует начальную форму слов и валидный JSON-массив.
5. **Очистка** (`clean_llm_json`): убирает markdown-обёртки, исправляет trailing commas.
6. **Инжест** (`memory.ingest_parsed_fact`): создаёт символы, гиперсвязи, связи `PREDICATE`/`SUBJECT`/`OBJECT`, при `CLASSIFY` — `IS-A`.
7. **Фиксация** (`mark_chunk_processed`): отмечает чанк как обработанный.

---

## 🛡 Устойчивость к сбоям

- **Три попытки** на каждый чанк с задержкой `2^attempt` секунд.
- **Хэши чанков** в таблице `parsed_chunks` — повторный запуск не дублирует данные.
- **Транзакции** в `agent/database.py` — при падении БД не портится.

Прервать и продолжить можно в любой момент:

```bash
# Упало на 3000-м чанке
python -m parsing.main
# Запусти снова — продолжит с 3000-го
```

## 📊 Что на выходе

После успешного парсинга в БД:

| Таблица | Что хранит |
|---------|-----------|
| `symbols` | Абстрактные символы (S), их канонические формы и парадигмы |
| `facts` | Гиперсвязи (P) — факты с ролями и предикатами |
| `links` | Ассоциативные связи (L): `PREDICATE`, `SUBJECT`, `OBJECT`, `IS-A`, `FOLLOW` |
| `parsed_chunks` | Хэши обработанных чанков |

Проверить содержимое:

```bash
sqlite3 data/output/ah_memory.db
.tables
SELECT COUNT(*) FROM symbols;
SELECT COUNT(*) FROM facts;
SELECT COUNT(*) FROM links;
```

## ⚠️ Частые проблемы

| Проблема | Решение |
|----------|---------|
| `401 Unauthorized` от GigaChat | Проверь `.env`, обнови ключи |
| Чанк не обрабатывается | Удали `data/output/ah_memory.db` и запусти с `--reset` |
| Мало символов (< 150) | Увеличь корпус или уменьши `window` в `split_and_group` |
| Долго работает | Используй `--test N` для отладки; в продакшене — запусти в `screen` |
